# Security Policy

`digital-menu` is a public, open-source project. Security is taken seriously, and vulnerabilities are handled privately so they can be fixed before being disclosed broadly.

## Supported versions

| Version | Supported |
|---------|-----------|
| `main` (latest) | ✅ |
| other branches | ❌ |

Only the latest production state (the `main` branch) receives security fixes.

## Reporting a vulnerability

**Do not** report security vulnerabilities through public GitHub issues. Please report them privately:

- **Preferred:** use GitHub **private vulnerability reporting**. If the repository supports it, the **Security** tab of the repository lets you submit a private advisory directly to the maintainer.
- **Fallback:** if private reporting is not available, contact the maintainer directly (Patricio Montes) via email or a private message on the platform where you found the project.

### What to include

When reporting, include:

- Affected file(s) and the exact version/commit.
- A clear description of the vulnerability and its impact.
- Steps to reproduce, if possible (minimal example).
- Any suggested fix, if you have one.

The more detail you provide, the faster the issue can be triaged.

## What to expect

- **Acknowledgement:** you will receive a reply within a reasonable timeframe acknowledging receipt of the report.
- **Triaging:** the report will be assessed for severity and validity.
- **Fix and release:** a fix will be prepared and released on `main`, with a note in the release and credit if you wish to be acknowledged.
- **Disclosure:** you will be kept informed of progress. Public disclosure is coordinated with you rather than announced before a fix is available.

## Acknowledgements

We value the community's help in keeping this project safe. With your permission, you will be credited for verified and fixed reports. If you prefer to remain anonymous, that is fully respected.
